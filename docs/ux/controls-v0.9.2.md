# v0.9.2 조작 · 보드 · 상단 내비 · 배경 파티클 — AD 설계 (문세라)

감독 지시: ① 하단 방향 버튼 패드 제거 → 보드(장면 그림) 확대, LH 처럼 키보드 + 스와이프 ② 배경에 은은한 파티클, 단계마다 배경 톤에 맞춘 색 ③ 상단 아이콘 내비로 남은 단계를 한눈에.
게시 리비전은 바꾸지 않았다(새 리비전 게시는 감독 승인 사항). 커밋 없음.

## 1. 비교 — 지금 EB vs LH

| | EB v0.9.1 | LH (참고) |
|---|---|---|
| 키보드 | 화살표 · WASD(e.code) — 이미 있음 | 같음 |
| 스와이프 | `touchstart/touchend` — **캔버스 위에서만**, **손을 뗄 때** 판정, 24px | `pointerdown/move` — 보드 칸 전체, **움직이는 중 거리 넘는 순간** 1회, 입력 종류별 거리(마우스 14 · 펜 18 · 터치 22, 칸 25% 이하), 축 비 1.3 |
| 화면 버튼 | 방향 패드 4개(56px, 세로 ≈130px 차지) | 없음 |
| 보드 크기 | `min(칸 폭, 칸 높이, 480)` · 칸 폭 520 제한 | `min(480, 100vw-32, 100vh-286)` |
| 조작 안내 | 첫 판 토스트 한 줄 | 입력 종류별 한 줄 + 보드 가장자리 표시 |
| 배경 연출 | CSS 격자 + 모서리 빛(정지) | 보드 그림 안에 반짝임 16 · 안개 4 · 불티 7, rAF, `?fx=0`/reduced-motion 이면 정지 |

**발견한 결함(전):** 가로 폰(740×360)에서 `#canvas-wrap` 의 flex `min-height:auto` 때문에 캔버스 크기가 칸 높이를 다시 밀어 올려 보드 아래쪽이 잘리고 방향 패드는 화면 밖에 있었다(캡처 `eb-ctrl-before-mobile-740x360-landscape.jpeg`). 또 400px 폭에서 긴 제목이 ⭐ 칩을 밀어내 보이지 않았다.

## 2. 바꾼 것

**입력** — 패드 · `.dirbtn` · `flashDirBtn` 삭제. 방향 피드백은 원래 있던 보드 가장자리 빛(`flashBoardEdge`)이 맡는다.
스와이프는 LH 방식으로 교체: `#canvas-wrap`(보드 칸 전체, 보드 바깥 여백 포함)에서 pointer 이벤트, 이동 중 판정, 마우스 끌기도 됨. 모달이 열려 있으면 무시(모달 키보드 탐색 그대로). 탭 방향(가장자리 탭)은 넣지 않았다 — 잘못 누름이 늘고 글 없는 조작 읽기에 도움이 안 된다.
`regainFocus`(광고 뒤 포커스) · 햅틱 · 사운드 · 리더보드 · 데일리는 건드리지 않음.

**조작 안내(글 최소)** — 세션에서 판을 처음 시작할 때 한 번 보드 아래쪽에 작은 알약: 터치 기기 = 손끝 점이 옆으로 미끄러지는 그림 + `SWIPE`, 키보드 기기 = 키캡 `← ↑ ↓ → / W A S D`. 첫 수 또는 4.5초 뒤 사라짐, 입력 통과, 새 저장 키 없음. 첫 방문 토스트 · 튜토리얼 문구도 "버튼을 탭" → 스와이프 · 방향키 · WASD 로.

**보드 크기** — `#canvas-wrap` `min-height:0` · 폭 520 제한 해제 · 여백 8→6, `resizeCanvas` 상한 480 → 640(장면 원본 512px — 데스크톱 1배율에서 1.25배 이상은 흐려짐이 보인다). `ResizeObserver` 로 상단 내비 · 설명 바가 생기고 없어질 때도 다시 맞춘다(전에는 창 크기 변화 때만).
가로 화면(가로/세로 ≥ 1.3)에서는 단계 설명 바를 보드 아래가 아니라 왼쪽 여백에 띄워 보드가 세로 전체를 쓴다.

| 뷰포트 | 전 (px) | 후 (px) | 비고 |
|---|---|---|---|
| 세로 400×760 | 384 (그림 368) | **400 (그림 396)** | 2차(PD 결정) — 아래 '세로 2차' |
| 데스크톱 가로 1280×720 | 480 | **626** | 한 변 +30%, 넓이 +70% |
| 모바일 세로 360×640 (터치) | 344 (그림 330) | **360 (그림 356)** | 2차 |
| 모바일 가로 740×360 (터치) | 344 이나 아래 잘림 · 패드 화면 밖 | **266 전부 보임** | 조작 불능 → 스와이프로 조작 |

**세로 2차(PD 결정)** — 세로 화면만(`@media (orientation: portrait)`): 보드 칸 여백 0 · 캔버스 테두리 없음 → 캔버스 = 화면 폭, 보드 안쪽 여백 2% → 0.6%(셸에서 `renderer.resize` 를 덮음, 엔진 파일은 그대로), 보드는 남는 높이 가운데. 헤더 한 줄 압축(여백 10→6, 제목 1.15→1rem, 스탯 라벨 줄바꿈 없음). 단계 설명 바는 오버레이로 보드를 가리는 대신 한 줄로(그림 34px + 이름 + 설명 말줄임, STEP 라벨은 상단 내비가 대신) — 높이 48px. 가로 · 데스크톱은 그대로. (괄호 안 "그림" = 보드 안 장면 그림 한 변.)

**상단 HUD · 아이콘 내비** — 진행 막대(`CHAPTER 1 · 3 / 11`) 자리를 아이콘 줄로 바꿈.
- Chronicles: 지금 장 로마 숫자 배지 + 11칸(지난 단계 = 장 색 채움 · 지금 노리는 단계 = 흰 고리 + 은은한 맥박 · 남은 = 윤곽, 마지막 장면 칸은 네모) + 남은 수 숫자 하나 + 구분선 + 다른 장 배지(끝냄 = 채움 ✓ · 열림 = 윤곽 · 잠김 = 점선 흐림).
- Daily: 단계가 없는 대신 판의 별 목표 4개 `★64 ★128 ★256 ★512` — 판 최고 블록이 닿으면 채움, 다음 목표 강조(1024 붕괴 뒤에도 유지).
- Endless: 단계가 없어 숨김.
- 헤더: Chronicles 제목은 장 이름만(`COLLECTION ·` 제거), `STEP x/11` 스탯은 내비와 겹쳐 숨김 → 제목 | 이번 판 ⭐ | 지갑 ⭐ | ⚙. 긴 제목은 말줄임(칩을 밀어내지 않게).

**배경 파티클** — `src/bg-fx.js`(새 파일, 외부 리소스 0) · `<canvas id="bg-fx">` 화면 고정 맨 뒤 레이어. 보드 캔버스가 위를 덮어 보드 안에는 비치지 않는다.
- 장마다 데이터(`SG.BgFx.THEMES`): 원시 지구 = 위로 오르는 불티(ember) · 인류 문명 = 옆으로 흐르는 먼지 · 꽃가루(dust) · 태양계 = 반짝이며 아주 느리게 흐르는 별(star) · 그 밖(Endless 스킨 없음 등) = 옅은 별가루.
- 단계마다 색: 지금 단계 배경 그림(`bg-step-NN.webp`, 없으면 장 `board-bg.webp`)을 24×24 로 줄여 밝은 쪽 20% 평균 톤을 뽑고, 장 기본색과 45~70% 섞는다 → 단계가 바뀌면 입자 색도 그 장면 톤으로.
- 가독성: 1~3px, 최대 불투명도 .6, 흰 심 + 색 번짐 스프라이트.
- 부하: 입자 수 = 화면 넓이/15000(최소 16 · 최대 36, 코어 ≤4 또는 메모리 ≤2GB 면 ×0.6), 30fps, DPR 상한 1.5, 색마다 미리 그린 스프라이트. 광고 중 · 플랫폼 일시정지 · 로비(불투명 화면) · 탭 숨김이면 그리지 않음. `prefers-reduced-motion` 이면 정지한 한 장면만.
- 설정에 연출 끄기 옵션은 없다(사운드셋 · 햅틱뿐) → 새 설정은 만들지 않았다. 필요하면 PD 판단.
