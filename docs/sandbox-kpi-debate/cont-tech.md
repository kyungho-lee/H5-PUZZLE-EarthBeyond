# CONTINUE 교차 피드백 A라운드 — 기술 · UX 구현 (한도윤 · 2026-10-01)

_읽은 것: `continue-brief.md`, `pd-final-spec.md` §2-3, `strata-gate.md` §2. 코드: `collection.js` `recordMerges`(190–220), `daily.js` 광고 쿼터(153–190), v0.9.1 `index.html` `collectionGameOver` · `collectionContinueWithAd` · `startCollection`, `session-rules.js`, `playgama.js` `requestRewardedAd`. 브라우저 · src 수정 없음._

## 0. 판단 전에 짚을 코드 사실 3개

1. **진행은 이미 판을 넘어 보존된다.** `recordMerges` 는 장면(acquiredSizes/Steps)을 테마 저장에 누적하고, 장 완성 = 마지막 크기(1024)를 **한 번** 만드는 것이다. 즉 "처음부터 다시"는 갤러리가 아니라 **보드(최고 칸)** 만 처음부터다. 플레이어가 느끼는 손실은 "장면을 잃음"이 아니라 "다시 1부터 쌓아야 함"이다 → D(체크포인트)는 새 저장 없이 **기존 acquiredSizes 에서 파생**할 수 있다.
2. **광고 쿼터는 사실상 판당이다.** `startCollection()` 이 매 판 `SG.Daily.resetAdQuota()` 를 부른다(이름은 "일일 3회"지만 판마다 0으로). 여기에 광고 CONTINUE 를 얹으면 "질 때마다 +1 life" 와 구조적으로 같아진다 — #10 의 정확한 금지 문구. 광고 CONTINUE 를 하려면 이 리셋부터 고쳐야 한다(키는 그대로, 리셋 호출만 제거 → 진짜 하루 3회).
3. **지층과의 상호작용.** 지층 생성 크기는 보드 최고에 따라 오르고(`gradedTiers`), 화석 경계도 최고 기준이다. 체크포인트로 높은 칸을 깔고 시작하면 생성 크기도 그 즉시 따라 오른다 → 체크포인트 시작 칸을 너무 높게 주면 sim 게이트(25~45%)가 깨진다. 값은 디자인 sim 으로 정해야 한다.

## 2. 광고 CONTINUE 를 한다면 — Bridge 배선 (기록용, 권하지 않음)

- 흐름: 게임오버 → (규칙상 허용될 때만) 버튼 `📺 CONTINUE — watch an ad, clear the small tiles` (광고가 온다 · 무엇을 주는지 명시, #10 문구 요건). 탭 → `requestRewardedAdWithQuota('collection_continue')` → `SG.CG.requestRewardedAd` (Bridge `showRewarded`, `REWARDED_STATE_CHANGED` 의 `rewarded` 를 본 경우에만 granted).
- 실패 · no-fill: `failed` 또는 15초 타임아웃 → **쿼터 반환**(`refundRewardedAd`) + 버튼을 "광고 없음" 상태로 비활성 + PLAY AGAIN 에 포커스. 재시도 버튼은 두지 않는다(실패 반복 → 좌절 루프). mock/qa_tool 의 "실패=성공" 처리는 CONTINUE 에서는 끈다(심사 QA 에서 공짜 이어하기로 보이면 안 됨).
- 오디오: 이미 `_adAudioPause()`(효과음 음소거 + BGM AudioContext suspend) → `_adAudioResume()`. 광고 뒤 `resizeCanvas()` + rAF 1회(현행 CONTINUE 경로에 있음).
- 리듬: 리워드 직후 전면광고 금지 — `adRhythm.noteShown()` 을 리워드에도 호출해 90초 창을 공유.
- 계측: `ad_offer {format:'rewarded', placement:'collection_continue', granted, reason}` 는 이미 래퍼에 있음.

## 3. UX · 인지 근거 (해당되는 것만)

- **손실 회피 · 진행 리셋 좌절**: EB 의 손실은 "장면"이 아니라 "쌓은 보드"다. 갤러리 장면은 남는데 화면은 그걸 말하지 않는다 → **E 의 첫 줄을 "장면 6/11 — 지금까지 모은 장면은 그대로"** 로. 비용 0에 가까운 손실 프레이밍 교정.
- **목표 경사 효과**: 마지막 장면에 가까울수록 다시 할 확률이 오른다 → 게임오버 화면에 "다음 장면까지 최고 칸 256 / 512 (50%)" 처럼 **남은 거리**를 숫자로. 연표 띠(0.9.2)의 예고편.
- **진행 착시(endowed progress)**: D 의 "다음 판은 한 칸 앞에서" 가 정확히 이것. 0 에서 시작이 아니라는 느낌이 재시도를 끌어낸다. 단 성취감(기준 4)을 지키려면 시작 칸은 작게(sim).
- **피크엔드**: 판의 끝 = 게임오버 화면. 끝 장면을 "실패" 대신 "이번 판에 연 장면 N개" 로 끝내면 기억이 좋아진다(데이터 이미 있음: 이번 판 newSteps 집계만 추가).
- **선택 과부하 · 버튼 위계**: 지금 게임오버는 CONTINUE · END RUN · ⭐×2 · PLAY AGAIN · GALLERY · MENU 로 많다. 권장 위계: ① **PLAY AGAIN(가장 크게, 기본 포커스, Enter)** ② CONTINUE ⭐5(있을 때만, 보조) ③ 📺 ×2 보너스(작게, 명시) ④ GALLERY · MENU(텍스트 링크급). 기본 포커스가 광고 버튼이면 안 된다(실수 탭 = #10 opt-in 위반 소지).
- **타이머 금지**: "5초 안에 CONTINUE" 카운트다운은 압박 · 다크 패턴, 동작 줄이기 사용자에게도 나쁨. 넣지 않는다.
- **학습된 무기력**: 초보형(mixed) 봇 첫 클리어 중앙 14판. 이 구간은 CONTINUE 가 아니라 **F(정직한 보정) + D** 가 맞다 — CONTINUE 는 이미 거의 다 온 판을 구하는 도구이고, 계속 막히는 사람에게는 매판 같은 벽이다.

## 4. 추천 조합

**A(현행 유지: 별 · 판당 1회) + D(장 안 체크포인트, 기존 저장에서 파생) + E(게임오버 화면 재설계) + F(세션 한정 · 표시하는 보정). B(광고 CONTINUE)는 넣지 않는다. C 는 세션 첫 게임오버 1회 무료만 조건부로 검토(디자인 sim 이 지층 + D 와 합쳐 게이트 안이면).**

- 이유: #10 위험 0 · 저장 키 0 · 엔딩까지의 벽(1024 를 한 판에)에 직접 작동하는 것은 D 와 F 다. 광고 CONTINUE 는 #10 문구와 정면으로 겹치고, 지금 쿼터가 판당 리셋이라 더 나쁘다.
- 비용: D 3~5h + E 3~4h + F 2h + 테스트 · 확인 2h = **10~13h**(+ 디자인 sim). v0.9.1(10/5 동결) 범위를 넘으므로 **v0.9.2**. 10/5 전에 할 수 있는 것은 E 의 문구 2줄("모은 장면은 그대로" · PLAY AGAIN 기본 포커스) 0.5h 뿐.
- 예상 효과(정성 · 수치는 디자인 sim 몫): 게임오버 직후 이탈 감소(E), 1장 첫 클리어까지 판 수 감소(D · F), 판 길이는 유지 → 엔딩까지 누적 플레이 시간은 줄지 않고 도달률이 오른다.
- 별도 수정 권고(조합과 무관): `startCollection()` 의 `resetAdQuota()` 판마다 호출은 "일일 3회" 표기와 어긋난다 → 리워드 ×2 보너스에도 판당 3회라 #10 "every time" 해석 위험. 0.9.2 에서 하루 기준으로(키 그대로).
