## 2. 셀프 리플렉션 — 내 r1 의 약점

1. **배관만 봤다.** 가장 큰 KPI 병목(기획 sim: Chronicles 1장 클리어 0%, Endless 사실상 영구 잠금)을 코드에서 볼 수 있었는데 놓쳤다. 리더보드를 켜도 `ch1_clear` 는 비어 있고 Endless 순위는 아무도 못 연다 — 내 P1 · P5 의 효과는 지층 없이는 반쪽이다.
2. **부팅 10초를 과장했다.** 아카이브 실측 loadingTime 480ms(운영 r1). 10초는 최악 상한일 뿐이다. 6~8h · 저장 병합(중위험) 비용은 측정 창 전에 쓸 만한 일이 아니다. 남길 것은 늦은 `game_ready` 보장 + iframe 포커스(합쳐 1h)뿐이다.
3. **판 저장 비용을 부풀렸다.** RNG 상태 직렬화를 걱정했지만 Chronicles 는 `makeRng()`(Date.now 시드)라 재현이 필요 없다 — 이어할 때 새 시드면 된다. 대신 진짜 의존을 놓쳤다: 지층이 들어가면 저장할 상태(화석 층 · 기본 크기)가 바뀐다. 판 저장은 **지층 뒤**에 해야 두 번 안 만든다.
4. **체크 #10 을 남에게 넘겼다.** CONTINUE(AD) 를 보고도 "운영 판단"으로 넘겼는데, 고치는 건 코드 10줄이고 카탈로그 사람 심사 위험이다. 기술이 비용을 말했어야 했다.
5. **`analytics.send` 를 몰랐다.** 체크리스트 #14 를 직접 읽지 않았다. SDK 래퍼 담당이 놓친 것.
6. **시간축이 없었다.** 10/5 게시 → 10/6~10/11 측정 동결 → 10/12 이후, 그리고 10/6 까지 LH 우선 · PC 부하 규칙. 내 r1 의 합계(21~30h)는 이 창에 맞춰 자른 것이 아니었다.
