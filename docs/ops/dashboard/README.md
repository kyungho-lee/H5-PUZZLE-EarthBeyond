# 대시보드 스크린샷 리포트 — 운영 절차 · 템플릿 (EB)

_서비스 운영 강민재 · 제안 문서(2026-10-07). 최초 적용 예: `2026-10-07.md`._

목적: 캐비닛 웹 Metrics 탭에만 있는 지표(세션 · 바운스 · 평균 플레이 · 깔때기 · 리텐션 · 기기별 차트)를 **같은 틀로** 기록해서 일자별로 비교할 수 있게 한다. 이 화면은 MCP 로 볼 수 없으므로 **캡처는 감독 또는 PD 가 Chrome 으로** 한다. 운영(강민재)은 캡처를 Read 로 읽고 MCP 로 교차 확인한 뒤 리포트를 쓴다. 캐비닛 쓰기는 하지 않는다.

## 1. 캡처 체크리스트 (감독 · PD)

공통 설정을 먼저 맞추고, 화면을 위에서 아래로 스크롤하며 찍는다.

| # | 설정 · 화면 | 이유 |
|---|---|---|
| 0 | 앱 EB → 좌측 Metrics → 상단 **Sandbox** 탭 선택 | 다른 환경 값과 섞이지 않게 |
| 1 | Device: **All Devices**, 기간: **Last 30 Days** (기본 캡처) | 기본 기준선 |
| 2 | KPI 카드 6개(Plays · Bounce · Avg Load · Game Ready · Avg Play Time · D1/D7) 전체가 한 화면에 | 숫자. 정의 툴팁(ⓘ)은 필요할 때만 |
| 3 | Plays & PlayTime — **Gameplays 차트**(기기 범례 포함) | 일별 추이 · 기기 비중 |
| 4 | **Avg Play Time 차트** | 기기별 체류 |
| 5 | **Engagement 깔때기**(세션 수 · Game Ready → 5m+) | 병목 위치 |
| 6 | **Bounce Rate Dynamic** 차트 | 일별 바운스 |
| 7 | **Retention 표**(코호트 · 신규 수 · D1~) 전체 | 표본 크기 확인용(신규 수가 반드시 보이게) |
| 8 | 대시보드 **게임 목록 행**(상태 · Plays · Revenue) | 공개 plays 와 대조 |
| 9 | (필요할 때) 같은 화면을 **Android · iOS 필터**로 각각, **Last 7 Days** 또는 **Choose Date** 한 일자로 | 모바일 · 최근 일자 · 일별 깔때기 |

캡처 팁
- 차트는 **마우스 포인터를 올려 툴팁 값**이 보이는 상태로 한 장 더 찍으면 판독 오차가 사라진다(일별 값이 중요한 날).
- 경고 문구(예: 표본 부족 경고)가 있으면 반드시 같이 찍는다.
- 가능하면 페이지 텍스트 추출(PD)을 같이 준다 — 숫자 오독이 줄어든다.
- 캡처 일시와 선택한 기간 · 기기를 파일 이름이나 메모에 적는다.

## 2. 운영이 하는 일 (캡처를 받은 뒤)

1. 캡처를 직접 Read 로 읽는다. 차트 값은 눈금으로 읽고 **「차트 판독 ±n」** 으로 표시한다.
2. MCP 읽기 전용 교차 확인:
   - `get_sandbox_traffic` — 트래픽 런 기록(시작/종료 · kind · 소진 비율 · 게시물).
   - `get_sandbox_state` — 게시 시점 · 리비전.
   - `get_application` — 심사 상태 · 활성 아카이브(버전).
   - `get_game_telemetry_analytics` — **일 단위로 나눠 호출**(넓은 범위는 HTTP 500 이 난 적 있음). `schema_version` · period · `event_sequences` 표본 · `page.next_cursor` 를 읽고, **null/없음을 0 으로 읽지 않는다.**
3. 오가닉 판정 규칙(필수): 해당 일자에 활성이던 트래픽 런 · 게시물 · 버전 변경을 먼저 표로 놓고, 겹치면 「오가닉 미확인」 으로 쓴다. 런이 없는 일자의 값만 오가닉 후보로 본다. 유입 경로 차원이 없으면 그 한계를 적는다.
4. 숫자마다 출처 표시: 【캡처】 · 【MCP】 · 【계산】 · 【판독】.
5. 시간 단위 · 기간 추정 대신 일자 · 세션 · 비율로 쓴다. 판단은 PD 몫이므로 「제안」 으로만 적는다.

## 4. 점검 시점 (제안)

- 새 빌드 게시 · 트래픽 런 시작/종료 뒤의 첫 온전한 일자.
- 리텐션 코호트가 닫힌 뒤(D1 은 코호트 일자 다음 날이 지나야 의미).
- 감독이 지시할 때. 같은 캡처 세트를 반복해야 비교가 되므로 §1 항목은 매번 같은 순서로 찍는다.
- 비교는 항상 직전 리포트의 같은 칸과 한다. 표본이 30 미만이면 비교 결론 금지.

## 5. 하네스 반영 제안 (PD 판단 · 나는 수정하지 않음)

1. `docs/win-condition.md` 지표 표의 「세션 · 평균 플레이 · 재방문 — 아직 모름」 을 「캐비닛 웹 Metrics 탭에서 확인(MCP 로 불가) — 캡처 절차는 `docs/ops/dashboard/README.md`」 로 갱신, 그리고 지금 단계 절(10/5 게시 · 10/7 SHARE · v0.9.1)을 실제(v0.9.2 게시 10/3 19:50Z · 런 10/3~10/6)에 맞게 갱신.
2. `docs/team-roles.md` 의 서비스 운영 행 · 위치 표에 「대시보드 캡처 리포트 → `docs/ops/dashboard/`」 추가. 캡처 담당은 감독/PD 로 명시.
3. 승리 조건 지표 판독에 「트래픽 런 구간 표시 필수」 원칙 한 줄 추가(오가닉 오판 방지).
4. 기술총괄 확인 요청: 세션 요약의 성능 샘플(`observed_sessions: 0`) 미수집 원인, 그리고 유입 경로를 구분할 수 있는 이벤트 속성 추가 가능 여부. 가능하면 대시보드 밖 보조 근거가 된다.
