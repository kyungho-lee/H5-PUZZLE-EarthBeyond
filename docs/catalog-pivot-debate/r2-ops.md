## 4. 같은 앱에서 제목 · 커버 · 컨셉 변경 — 재심사가 붙는가 (읽기로 확인 가능한 범위)

| 변경 | 재심사 · 모더레이션 자동 발생? | 근거 | 확인 못 한 것 |
|---|---|---|---|
| 새 아카이브 업로드 + 샌드박스 게시(컨셉 · 그림 전면 교체 포함) | **아니오** | 「no submit, no certification, no moderation」 | 아카이브 콘텐츠를 Playgama 가 사후 열람하는지 |
| 폼 저장(제목 · 설명 · 개발자 코멘트 · 조작법 · 장르 등) | **아니오** | 「Saving does not submit anything to moderation」 | 제목 변경 시 다른 곳(공개 페이지 · 챌린지)에 즉시 반영되는지는 도구 응답에 없음 |
| 커버 교체 (`start_cover_upload` · `confirm_cover_upload`) | 도구 설명상 제출과 분리됨(폼 편집군) | tools.md 요약 | 커버 변경이 샌드박스 목록 썸네일에 즉시 반영되는지(`get_launch_steps.covers` 가 「NO_COVERS → 게시 다시」 를 요구하는 경우가 있음, 미확인) |
| 스크린샷 · 영상 교체 | 자동 심사 없음 | — | **MCP 에 도구가 없다 — 사람이 캐비닛에서**. 옛 6월 스크린샷 5장 · 영상이 남으면 새 컨셉과 어긋남 |
| 사람이 캐비닛에서 「제출」 누름 | **예 — 이것만 모더레이션을 부른다** | 「you press the button」 | 새 제출 시 이전 POSTPONED/반려 이력이 어떻게 반영되는지, 쿨다운(`lockedUntil: null` 현재) |
| 새 앱 생성 후 샌드박스 | 아니오(샌드박스는 심사 없음) | 위키 | 새 앱도 certification 이 필요한지: LH 는 form 만 `NO_CERTIFICATION` 으로 막혀 있고 sandbox · share 는 정상 → **샌드박스 게시에는 certification 불필요**로 보임(LH 관찰) |

- **결론**: 같은 앱에서의 컨셉 교체는 **심사 이력이 따라오긴 하지만 재심사 절차를 새로 시작하지는 않는다.** 이 앱의 최종 관문은 「Playgama 가 샌드박스 지표를 보고 고른다」 이며, 우리 쪽에서 낼 수 있는 심사 신호는 `developerComment` · 폼 설명 · 아카이브뿐이다.
- 따라서 **폼의 `developerComment` 와 설명문을 컨셉 교체와 같은 날 고쳐 두는 것**이 사실상 「다시 봐 달라」 는 유일한 우리 쪽 신호다(제출 아님). 문구는 사실만(「all art is drawn in code」 는 이미지 0 확인 후).
