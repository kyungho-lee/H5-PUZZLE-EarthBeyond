| 쟁점 | 기술 판정 |

## 2. 쟁점 입장

### T3 — 저장 · 리더보드 호환 (판정)

`collection.js` 를 끝까지 읽었다. 저장 형태: 키 `earthbeyond_collection_<themeId>` = `{ acquiredSizes, acquiredSteps, newSizes, claimedSizes, status, runs, clearRuns, … }`, 메타 키 = `{ activeThemeId, unlockedThemes, completedThemes }`. **완료 판정 · 장면 획득은 크기로** 한다(`recordMerges` → `sizeToStep[size]`), 테마별 `stepSizes` 를 이미 지원한다.

| 항목 | 1024 → 128 로 바꾸면 | 이전 필요? | 처리 |
|---|---|---|---|
| 저장 키 · 테마 id | 그대로 | **불필요** | id 고정 원칙 유지 |
| `acquiredSizes`(1~1024) | 1~128 은 같은 크기 = 같은 장면 칸. 256 이상은 무시됨 | 불필요 | 그대로 |
| `acquiredSteps`(1~11) | 9~11 이 남으면 `gallery_total` 이 8 을 넘는다 | **필요(작음)** | `loadTheme` 에서 크기로 다시 계산 · 범위 밖 제거 |
| 진행 중(128 을 이미 만든) 테마 | `status: active` 인데 목표는 이미 달성 | **필요(작음)** | 불러올 때 128 이 있으면 `completed` 로 올리고 다음 시대 해금 |
| 어떤 8장면을 고르나(11 → 8) | 그림 · 이름만의 문제(표시층) | 불필요 | 크기 1~128 에 새 그림 8개를 붙이면 끝 |
| `chN_clear` (값 = 깰 때까지 판 수) | 1024 깊이 판 수 → 128 깊이 판 수, 판을 이어 가면 "판"의 뜻도 바뀜 | id 는 그대로 | 캐비닛상 6개 모두 `log_only`, 샌드박스 리더보드는 v0.9 에서 꺼짐 + 3 played → **항목이 사실상 0**. 같은 id 를 쓰고 빌드 경계 날짜만 기록. 섞인 항목이 보이면 그때 새 id(감독 승인) |
| `gallery_total` | 최대 33 → 24 | 불필요 | 점수 뜻은 "모은 장면 수" 그대로 |
| 지층 `WINDOWS`(id 키) | 128 깊이에서 창 6/7/7 값은 디자인 sim B 로 다시 정함 | 불필요 | 값만 |

**결론:** 디자인의 "옮겨야" 와 내 "id 고정" 은 서로 다른 층의 얘기였다. **키 · id · LB id 는 고정, 불러오기 정리 함수 1개(+ 테스트) 0.5일.** 실제 영향받는 플레이어는 거의 없다(3 played) — 그래도 정리 함수는 넣는다(로컬 테스트 · 감독 기기 저장이 깨지지 않게).

### T4 — 장면 수별 일정 (판정)

기술 고정 비용(장면 수와 무관): 어댑터 + dataURL 다리 2일, 저장 정리 0.5일, 게이트 0.25일, QA(게시 페이지 · 모바일 · 동작 줄이기 끔) 1일.
AD 일수는 r1-art 기준(원시 지구 11 + 배경 ≈ 3~4일, 전 시대 33 ≈ 10~11일)을 장면 수에 비례로 옮긴 **추정**.

| 첫 빌드 범위 | 장면 수 | AD(추정) | 기술(같은 기간 병행) | 빠른 게시일(10/3 착수) | 기술 쪽 위험 |
|---|---|---|---|---|---|
| 원시 지구 1시대 · 8장면 | 8 | 3 | 어댑터 2 + 문(판 잇기) 2 + 첫 30초 1.25 + 저장 0.5 + QA 1 = **6.75** | **10/10~11** (기술이 늦게 끝남) | 문을 넘은 사람(디자인 sim: 봇 72% · 초보 47%가 약 2.5분에 도달)이 바로 **빈 시대**를 만난다 → 아래 처리 필요 |
| 2시대 · 16장면 | 16 | 5~6 | 같음 | 10/11~12 | 문 1개만 실제로 열림 |
| 3시대 · 24장면 | 24 | 7~8 | 같음 | 10/13~14 | 없음(일정만) |
| 현행 깊이 33장면 | 33 | 10~11 | 문 없음이면 4.75 | 10/16+ | 판 잇기 불가(디자인 sim: 1024 로 이으면 둘째 시대 1%) |

- **1시대 첫 빌드는 기술적으로 가능.** 단 문 뒤를 막지 말고 **"다음 시대는 곧 — 지금은 같은 보드로 계속"(같은 옷의 Endless)** 으로 잇는다. 판이 끝나지 않으니 5분 생존을 깎지 않는다. 해금 플래그 하나(0.25일, 문 처리에 포함).
- **AD 의 "나머지 시대는 실루엣으로 잠금"**은 판 잇기(Time Gates)와 함께면 위 처리로 대체해야 한다(실루엣만 있는 시대에 플레이어가 들어가면 안 됨). 갤러리에선 실루엣 OK — LH 어댑터의 실루엣 캐시를 그대로 쓴다.
- **병목은 기술이다.** 첫 30초 · 어댑터 · 문 · 저장 · 운석(1.5)까지 다 하면 기술 약 8.25일, 한 사람이 순서대로. 그래서 **운석은 C 첫 빌드에서 뺀다**(1시간 sim 판정만 디자인이 먼저).

### T1 — 그래픽 컨셉: **위임(AD)**. 기술 조건만: 무엇이든 `drawTile(ctx, step, cx, cy, size, opts)` + `drawBackground` 인터페이스면 붙는다. 안 2(판화 망점 · 해칭)는 타일 캐시가 필수(캐시 없이 매 프레임 그리면 비쌈). 안 1 이 기술 위험이 더 낮다.

### T2 — 진행 구조: **디자인 「Time Gates」 지지(기술 가능 확인).** 128 은 설정 한 줄, 판 잇기는 LH `afterClear` 같은 순수 함수 + 셸 흐름 교체 1.5~2일. v0.9.1 지층은 시대마다 새로 시작하면 그대로 쓴다(`strata.newRun(chapterId)` 가 이미 장 단위).

### T5 — SHARE: **C 빌드에.** 라이브옵스 3링크 안이 채택되면 v0.9.1 링크 전에 T6 를 해야 한다(부스트를 60% 구멍에 붓지 않도록). 두 결정은 묶어서 내야 한다.

### T6 — 10/4 까지 첫 30초를 v0.9.1 에 (판정)

| 항목 | 10/4 가능? | 비용 | 이유 |
|---|---|---|---|
| F2 첫 판 그림 선로드 | 가능 | 0.25 | 셸 부팅 몇 줄 |
| F4 첫 판 배너 끔 + 첫 2분 전면광고 0(90→120초) | 가능 | 0.2 | 상수 · 호출 위치, `session-rules` 테스트 있음 |
| F3 손가락 스와이프 안내 | 가능 | 0.5 | 캔버스 오버레이, 첫 입력에 사라짐 |

- **권고: 넣지 않는다**(SHARE 가 C 빌드로 가는 한). 트래픽 없는 빌드에 넣으면 효과를 못 재고, 같은 하루로 C 빌드가 하루 당겨진다. 예외: T5 에서 10/7 v0.9.1 링크가 채택되면 **넣는다**(F2 · F4 · F3 · F5만, 버전 v0.9.1 재빌드 해시로 구분).

### T7 — 운석 예고: **1시간 sim 게이트 + C 첫 빌드에선 제외.** 반려 사유 "독창적 메커닉"에는 Time Gates(판이 시대를 넘어 이어짐)가 먼저 답한다. 운석은 v0.9.3 후보 — 코어 무수정으로 넣을 수 있다는 것만 확인해 둔다(T4 병목 때문).
